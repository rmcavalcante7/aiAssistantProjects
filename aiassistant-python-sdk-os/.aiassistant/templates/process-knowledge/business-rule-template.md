# Rule Name

## Owner

Process or component that owns the rule.

## Purpose

Decision this rule makes.

## Source

Where input data comes from.

## Lookup Key

Fields used to identify records.

## Decision Criteria

Conditions and outcomes.

## Output

Produced field, status, payload, or side effect.

## Missing Data Behavior

Behavior when input is missing or invalid.

## Operational Effect

How the result affects the next step.

## Boundary

What this rule must not decide.

## Evidence

Code, API, transaction, or example supporting the rule.
